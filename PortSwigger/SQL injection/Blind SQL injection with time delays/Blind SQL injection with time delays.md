# Описание
Уязвимость «слепой» SQL-инъекции, при которой приложение не возвращает результаты SQL-запроса и не отражает ошибки СУБД. Запрос выполняется синхронно, поэтому  можно инициировать искусственную временную задержку в ответе сервера, чтобы подтвердить наличие инъекции. Техника служит базой для дальнейшего извлечения данных через условные задержки.

## Риски
- **Скрытая утечка данных**: после подтверждения возможна эксфильтрация конфиденциальной информации через условные задержки.
- **Обход защитных механизмов**: атака не оставляет следов в HTTP-ответах, WAF и системы мониторинга могут не обнаружить её.
- **Компрометация учётных данных**: получение логинов и паролей, включая администратора.
- **Полный захват приложения**: управление пользователями, данными, настройками.
## Рекомендации

- **Использовать параметризованные запросы** (prepared statements) для всех SQL-операций.
- **Применять ORM** с автоматическим экранированием.
- **Внедрить строгую валидацию** входных данных: белые списки для cookie и параметров.
- **Ограничить права учётной записи приложения**: запретить доступ к системным функциям задержки (`pg_sleep`, `SLEEP`, `WAITFOR`, `dbms_pipe`).
