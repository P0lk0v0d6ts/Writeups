# Описание
Внедрение конструкции `UNION SELECT` с обращением к встроенным переменным/функциям, возвращающим версию СУБД. Полученные сведения дают точное знание типа и версии СУБД, что позволяет подобрать эксплойты под конкретную конфигурацию.
## Обнаружение/Идентификация
В ходе выполнения работа, было установлено, что  использование SQL-конструкции 
`' UNION SELECT @@version,NULL -- -`, позволяет выводить технические данные приложения. На рисунке 1 представлена идентификация количества столбцов для выполнения запроса UNION.

## Риски
- **Раскрытие точной версии и патч-уровня СУБД** — атакующий подбирает публичные эксплойты под конкретную версию.
- **Эскалация атаки** — знание версии позволяет перейти к эксплуатации известных уязвимостей СУБД.
- **Компрометация всей базы данных** — при наличии прав на чтение системных таблиц возможна дальнейшая утечка данных.
## Рекомендации
- **Использовать параметризованные запросы** (prepared statements) для всех SQL-операций.
- **Внедрить строгую валидацию** входных данных: белые списки для полей фильтрации, отсечение специальных символов (`'`, `--`, `UNION`, `#`).
- **Включить WAF** для блокировки классических SQL-инъекций и сигнатур `UNION SELECT`.
